**Clean Code — 34 / 40**
- Functions are short and well-separated: `drawHP`, `showIntro`, `enemyTurn`, `useItem`, and `setupEnemy` are all clean and single-purpose
- **Naming** (−2) — `c` at Game.cpp:93 for the player's menu choice and `p` at Game.cpp:79 for the Potion item are too short; `dmg` is acceptable

  Single-letter variable names outside of loop counters require the reader to track their meaning from context — `c` could be a character, a count, or a choice, and only reading several lines ahead resolves the ambiguity.

  ```cpp
  // Game.cpp:79 — 'p' used for a Potion item object
  Item p("Potion", Item::Type::Potion, 20);
  inventory.addItem(p);

  // Game.cpp:93 — 'c' used for the player's action menu choice
  int c;
  std::cout << "\n1.Attack 2.Fireball 3.Heal 4.Item\n";
  std::cin >> c;
  ```

- **Magic numbers** (−2) — heal amount 20 appears twice, fireball bonus 15, and enemy variance `rand() % 11 - 5` without named constants

  A magic number that appears in two places (heal amount 20 in both playerTurn and useItem) means a balance change requires finding and updating both, with no guarantee they stay in sync.

  ```cpp
  // Game.cpp:106 — hardcoded 20 for self-heal in playerTurn
  player.heal(20);

  // Game.cpp:129 — same hardcoded 20 for potion heal in useItem; no named constant linking them
  player.heal(20);

  // Game.cpp:102 — magic 15 for fireball bonus, no named constant
  dmg = player.getATK() + 15;
  ```

- **Note** — `useItem()` heals but doesn't remove the item from inventory, giving infinite healing

  An item system that never decrements inventory allows the player to heal indefinitely at zero cost, collapsing any difficulty the game intends — any enemy becomes trivially defeatable by cycling between damage and healing.

  ```cpp
  // Game.cpp:123 — useItem() heals player but inventory.removeItem() is never called
  void Game::useItem() {
      if (inventory.isEmpty()) { std::cout << "No items\n"; return; }
      std::cout << "You used a Potion!\n";
      player.heal(20);   // item is consumed from player's perspective but stays in inventory
  }
  ```
