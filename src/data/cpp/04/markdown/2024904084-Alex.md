**Heap / Dynamic Memory — 8 / 10**
- Inventory Rule of Three correctly applied (`std::vector<Item>*` with new/deep copy/delete)
- Game allocates Character* hero and Inventory* inventory; both deleted in ~Game()
- **Inventory stores vector via raw pointer unnecessarily** (−1) — `std::vector<Item>` by value would serve identically with zero complexity

  The whole point of `std::vector` is that it manages its own heap memory; wrapping it in a raw pointer creates Rule of Three obligations (manually written copy ctor, copy-assign, destructor) for no benefit over simply declaring the vector as a value member.

  ```cpp
  // Inventory.hh — vector held via raw pointer
  private:
      std::vector<Item>* items;   // requires full Rule of Three
  // Simpler alternative: std::vector<Item> items;
  // The vector manages its own memory; no new/delete needed
  ```

- **Game missing copy = delete** (−1) — no declared copy ctor/copy-assign; accidental copy would cause double-free

  Game holds raw owning pointers (`Character* hero`, `Inventory* inventory`); without `= delete` on the copy constructor and copy-assignment operator, the compiler silently generates shallow-copy versions that copy the pointer values — two Game objects would then both try to `delete` the same memory in their destructors.

  ```cpp
  // Game.hh — no copy protection declared
  class Game {
  public:
      Game();
      ~Game();
      void run();
      // Game(const Game&) = delete;          // missing
      // Game& operator=(const Game&) = delete;  // missing
  private:
      Character* hero;    // raw owning pointer
      Inventory* inventory;  // raw owning pointer
  ```
