## Overall

"Deep-Sea Prison: Descent Order" is a One Piece-themed prison-break RPG where the player chooses one of five Straw Hat crew members (Luffy, Zoro, Nami, Sanji, or Usopp), each with distinct stats and passive abilities, then fights through three floors of randomised room events before facing Warden Steelmark in a two-phase boss fight. The game ends with a clean win/lose screen and a run summary. The design is well thought out: each role has a meaningful passive that changes how you play (Luffy heals after skirmishes, Zoro gets a burst first strike, Nami gets better loot and fewer charge hits, Sanji's flee window is wider, Usopp's potions are stronger). Story flavour is consistent throughout, with warden-frame ASCII panels for key story beats. The main scoring gaps are the 163-line `combatEncounter` function, no inheritance, and scattered magic numbers throughout the combat and event code.

## Bonus

**Bonus score: 7 / 10**

Five playable characters with meaningfully different passives is a strong design choice — this is not five re-skinned clones, each role actually changes how you approach combat (Luffy can trade HP for the win and recover, Zoro bursts early and coasts, Nami plays the odds, Sanji runs when needed, Usopp stretches every tonic). The warden-frame ASCII panels for key story beats show care for presentation. The `operator<<` on Inventory that deduplicates items into "x2" output is a small but real quality-of-life touch.

What holds the bonus back: the story flavour is thin in the actual combat loop — it is effectively the same fight loop for all six enemy types, differentiated only by stat values. There is no moment equivalent to Mike's Q&A mechanic or the Resident Evil emotional premise. The five-character passive system is the creative centrepiece, and it is well executed, but the game world itself (generic warden prison) does not have the same weight or originality. Still a solid, complete RPG built around a coherent One Piece homage.

**Clean Code note:** The main fix is `combatEncounter` — extract `handlePlayerTurn()` and `handleEnemyTurn(bossMode)` and the function becomes readable at a glance. Name the probability constants (`kBaseGruntLootChance`, `kBossPhase1Threshold`, etc.) and the game loop becomes self-documenting. Adding even a minimal `Enemy` class (just stat constructor + name) would unlock the inheritance section for free.
