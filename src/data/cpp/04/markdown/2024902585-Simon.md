- **Raw owning `Character*` with no destructor** (−3) — Game destructs without deleting player_ on exit path; Rule of Three violated; `std::unique_ptr<Character>` is the fix

  Without a destructor, the heap-allocated Character is never freed when Game goes out of scope — and without a copy constructor, any accidental copy of Game would leave two objects believing they own the same pointer, causing a double-free.

  ```cpp

  // Game.cpp:130 — allocated here in createPlayer()
  player_ = new Character(name, hp, atk, def);
  // Game.cpp:32 — deleted only in resetGame(), never in a destructor
  delete player_;
  ```

The main area to address is the raw `Character* player_` in Game: since everything else in the codebase is clean and thoughtful, converting player\_ to a `std::unique_ptr<Character>` would eliminate the memory leak on exit and complete an otherwise very disciplined design. GameData.cpp and UIRenderer.cpp at 30-34K also suggest some large functions within those files that could benefit from further sub-delegation.
