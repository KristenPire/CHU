  Without `size()`, any code that needs to know how many items are in the inventory cannot ask the Inventory directly — it must reach past the interface to the internal container, breaking encapsulation.

  ```cpp
  // operator<< is present, but size() is entirely absent
  ```

**Clean Code — 22 / 40**
- Character, Item, and Inventory methods are all short (1–5 lines); `run()` (~20 lines) reads as a clear high-level script

- **Canonical form entirely absent** (−10) — Inventory declares no copy constructor, no copy-assignment, no destructor; the compiler-generated defaults happen to work but the requirement is explicit implementation

  When the Rule of Three is not explicitly implemented, the class silently relies on compiler-generated shallow defaults; if the internal representation ever changes to include raw pointers, those defaults will cause double-frees and memory leaks with no warning.

  ```cpp
  // Inventory.cpp — only a default constructor exists; no copy ctor, copy-assign, or destructor
  Inventory::Inventory() {}
  // The compiler generates shallow-copy versions of all three missing members automatically,
  // but explicit implementation is required by the rubric
  ```

- **Note** — `"\\nA "` at Game.cpp:35 is a double-escaped sequence that prints a literal `\n` character; output reads `\nA Slime appears!` with a visible backslash

  A double-escaped newline causes the raw two-character sequence `\n` to appear in the terminal instead of a line break, making the game's output look garbled to the player from the very first encounter.

  ```cpp
  // Game.cpp:35 — \\n is a double-escaped sequence; prints a literal backslash-n
  std::cout << "\\nA " << enemy.getName() << " appears!" << std::endl;
  // Output: \nA Slime appears!   (with a visible backslash)
  // Should be: "\nA " or just std::endl before the message
  ```
