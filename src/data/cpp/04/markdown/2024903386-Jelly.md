  When escape sequences appear literally in output, every status line prints as a single run-on string with visible `\n` characters instead of the intended line breaks, making the HUD unreadable during play.

  ```cpp

  void Game::displayStatus() {
      std::cout << "\\n+----------------------------------------+\\n";
      std::cout << "| " << hero.getName() << "   HP: " << hero.getHP() << "/" << hero.getMaxHP() << "\\n";
      std::cout << "| Enemy: " << enemy.getName() << " HP: " << enemy.getHP() << "/" << enemy.getMaxHP() << "\\n";
      std::cout << "+----------------------------------------+\\n";
  }
  ```

- **`heroAttack()` duplication** (−0, included above) — Manually clamps damage `< 1 → 1` instead of delegating to `enemy.takeDamage(hero.getATK())`, duplicating the minimum-damage logic already in `takeDamage()`

  Duplicating the damage-floor logic means that if the minimum is ever changed to 2 or made conditional, it must be updated in both heroAttack() and takeDamage() separately — one will silently diverge.

  ```cpp
  void Game::heroAttack() {

      enemy.takeDamage(damage);
  ```

**Heap / Dynamic Memory — 9 / 10**
- Inventory correctly implements Rule of Three with `std::vector<Item>*`; all other Game members by value
- Minor deduction: `std::vector<Item>*` adds complexity where a value would be identical (−1)

  A raw pointer to a heap-allocated vector requires a full Rule of Three implementation (copy constructor, copy-assignment, destructor), whereas a `std::vector<Item>` value member gets all three for free from the compiler — the extra work buys nothing.

  ```cpp
  // Inventory.hh — raw pointer to heap-allocated vector
  private:
      std::vector<Item>* items;  // requires manual new/delete in all three canonical members
  // compared to: std::vector<Item> items;  // Rule of Zero, compiler handles everything
  ```
