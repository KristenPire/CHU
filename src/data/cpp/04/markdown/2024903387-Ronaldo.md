- **Naming conventions missing** (−4) — no trailing underscore on any private member; no named constants for any magic numbers (all player/enemy stats, flee chance inline); `using namespace std` in Game.cpp

  Without a trailing underscore (or any member prefix), every private field — `name`, `hp`, `atk`, `def`, `gameOver`, `victory` — looks identical to a local variable, making it genuinely difficult to tell at a glance whether a given assignment modifies state or a temporary.

  ```cpp

  using namespace std;
  // Game.cpp:8 — no trailing underscore; fields look like locals
  Game::Game()
      : player("Hero", 50, 8, 2),
        currentEncounter(0),
        gameOver(false),
        victory(false)
  // Game.cpp:51 — flee chance 7/10 as a magic number inline
  bool Game::attemptFlee() {
      return (rand() % 10) < 7;
  }
  ```

- **Style issues** (−3) — `std::vector<Item>* items` is an unnecessary raw pointer to a vector (a plain `std::vector<Item>` member is idiomatic); `// Enemies exactly as you defined` comment reveals spec-copying; committed rpg.exe binary

  Storing a raw pointer to a `std::vector` requires manually writing the full Rule of Three (copy ctor, copy-assign, destructor) for Inventory when `std::vector<Item>` as a direct member would manage all of that automatically and eliminate any risk of double-free or leak.

  ```cpp
  // Inventory.cpp:1 — raw pointer to vector; forces manual memory management
  Inventory::Inventory() {
      items = new std::vector<Item>();
  }
  Inventory::Inventory(const Inventory& other) {
      items = new std::vector<Item>(*other.items);
  }
  // ...copy-assign, destructor all needed due to this one design choice
  ```
