- **Rule of Three violated on Game** (−3) — Game owns `Character* m_player` and `vector<Character*> m_enemies` but has no destructor, no copy constructor, and no copy-assignment; memory is freed via `cleanup()` called manually at the end of `run()`, which does not protect against exceptions or accidental copies

  Using a manual `cleanup()` instead of a destructor means memory is only freed if `run()` reaches its last line normally — an exception, a `return`, or any early exit silently leaks every enemy and the player.

  ```cpp
  // Game.hh:9-22 — owns raw pointers, no destructor
  class Game {
  public:
      Game();
      void run();
  private:
      Character* m_player;              // raw owning pointer
      std::vector<Character*> m_enemies; // raw owning pointers
      void cleanup();                    // manual — not called by destructor
      // No ~Game(), no copy ctor, no copy-assign
  };

  // Game.cpp:120-124 — cleanup() called only at end of run()
  void Game::cleanup() {
      delete m_player;
      for (auto& enemy : m_enemies) { delete enemy; }
  }
  ```
