- **ANSI escape codes as raw literals** (−2) — `"\033[1;35m"` etc. embedded throughout without named constants; wrapping them would make color usage as readable as the rest of the code

  Embedded escape sequences like `"\033[1;31m"` are impossible to understand at a glance; a reader must memorize the ANSI table to know what color each code produces, whereas `Color::Red` or `BOLD_RED` is self-documenting.

  ```cpp
  // Game.cpp:244 — color codes appear as raw escape sequences
  std::cout << "\033[1;32mVictory! You have vanquished the shadow!\033[0m\n";
  // Game.cpp:250 — another raw escape sequence mid-string

  ```

- **Rule of Three violated on Game and Room** (−2) — both have destructors but no copy constructor or copy-assignment

  A class with a destructor that deletes raw pointers will double-free if copied — both the original and the copy will try to delete the same pointers when they go out of scope, causing undefined behavior.

  ```cpp

  Game::~Game() {
      delete player_;
      for (auto r : allRooms_) delete r;
  }
  // Game.hh — no copy constructor or operator= declared
  ```
