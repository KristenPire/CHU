## Overall

A solid RPG with three playable characters, a supply drop system, and two distinct win paths — defeating all enemies or collecting rare items. The game design shows genuine creativity and ambition.   Dead functions are misleading — a reader who sees `useItem()` in the file will reasonably assume it is part of the active code path and spend time understanding it, only to discover it has no callers; it also means the actual item logic in `combat()` and the dead copy in `useItem()` can silently diverge if one is updated.

**Inheritance — 0 / 10**
- Not used. The string comparisons in `combat()` that dispatch enemy-specific dialogue (`if (enemy.getName() == "Asara Soldier")`, `if (enemy.getName() == "Sayyad The Boss")`) are exactly what a virtual `onEncounter()` method would eliminate — an `EnemySoldier` and a `BossEnemy` subclass of `Character`, each overriding `onEncounter()`, would let the combat loop call `enemy.onEncounter()` without knowing the concrete type.

## Bonus

**Bonus score: 12 / 10**

Three playable characters with different starting loadouts, a supply drop system that auto-compares gear and keeps your best weapon, and two separate win paths — that's a lot of thoughtful game design on top of the baseline requirements. Most people just made one character and called it done.

The ASCII art for the legendary collectibles is a genuinely nice touch. There's real effort to make finding one feel like an event rather than just a flag flip.

**Clean Code note:** The code is split across well-named files and most functions are short and clear. The main issue is that `combat()` at 254 lines is doing too much at once — item selection, combat logic, and enemy AI all tangled together — and there's a dead `useItem()` function that was replaced inline but never removed. Pulling item handling into its own helper and deleting the dead code would make this much cleaner. Naming is strong elsewhere; `spawnRandomEnemy`, `searchCollectionBox`, and `zeroBasedIndex` are all good names.
