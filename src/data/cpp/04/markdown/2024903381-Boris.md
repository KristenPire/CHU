## Overall

A historical RPG set across the six Warring States campaigns, with two-choice diplomatic decisions before each boss and genuine consequences based on your choice. The operator overloading section is flawless and the Inventory canonical form is correctly implemented. The big weaknesses are zero inheritance, serious memory management bugs (double-free and leaked enemies in mid-story replacement), and a codebase padded with stub structures and empty helper functions that never do anything.

**Heap / Dynamic Memory — 4 / 10**
- Inventory canonical form is correct; Game destructor exists and iterates enemies
- **Double-free bug** (−2) — mid-story branches delete `currentEnemy` (which is `enemies[i]`), then the Game destructor deletes `enemies[i]` again → undefined behavior

  Deleting a pointer and then deleting it a second time through the original container is undefined behavior — in practice it corrupts the allocator's free-list, which can cause a crash at an unrelated point later in the program, making the bug extremely difficult to diagnose.

  ```cpp
  // Game.cpp:110-111 — currentEnemy deleted; enemies[i] still holds stale pointer
  delete currentEnemy;
  currentEnemy = new Character("Han Wang'an", 80, 25, 5);
  // enemies[i] is never updated — destructor will delete enemies[i] again:
  // Game.cpp:48 — Game destructor
  for (auto enemy : enemies) {
      delete enemy;   // double-free when enemies[i] was already deleted above
  }
  ```

- **Leaked replacement enemies** — new Character objects created mid-story are pointed to by `currentEnemy` but never tracked by `enemies`, so they are never freed
- **Note** — `exit(0)` on flee bypasses all destructors, leaking all heap memory

  `exit(0)` terminates the process immediately without unwinding the stack, so no destructor runs — the Game object, all its Character* enemies, and the Inventory* are all leaked, and any RAII resources (file handles, etc.) are not properly released.

  ```cpp
  // Game.cpp:356 — exit(0) on flee; all destructors skipped

  {

      exit(0);

  ```

**Inheritance — 0 / 10**
- Not used. The six warring-states bosses each have a distinct pre-battle scene and reward path — a `Boss` base class with a virtual `preRoundScene()` and six subclasses (e.g. `HanBoss`, `ZhaoBoss`) would let each campaign case call `currentEnemy->preRoundScene()` instead of embedding all six story branches inline in `run()`.

## Bonus

**Bonus score: 7 / 10**

The historical framework here is genuinely strong — fighting through the six warring states in historical order with two-choice diplomatic decisions before each campaign is a real design with real consequences, not just flavor text. The detail that forging Li Mu's surrender letter gets you a different reward than returning with intelligence shows actual thought about how choices should matter.

The flavor text for each campaign is readable and grounded in real history, which gives the whole thing a backbone that a lot of games in this course don't have.

**Clean Code note:** The `Game.cpp` structure is clear enough at the top level — `setup()`, `battle()`, and `displayStats()` are reasonably focused — but the big `run()` function doing all six campaigns as a giant switch statement is the obvious place to improve. Each case is essentially a full standalone scene that could be its own method (e.g., `hanCampaign()`, `zhaoCampaign()`), which would dramatically reduce run()'s length and make each campaign independently readable. The `GameUtils::showMessage()` overloads are a nice touch, though the utility structs (GameState, BattleResult) declared at the top of Game.cpp are never actually used in any meaningful way.
