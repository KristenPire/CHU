- **Missing `operator<<` for Character** (−2) — stats are printed inline in `showMenu()` by calling individual getters; no `operator<<` defined for Character or Entity

  Without `operator<<`, a Character object cannot be sent directly to an output stream; every display site must manually call `getHp()`, `getAtk()`, and `getDef()` in sequence, duplicating that formatting logic across the codebase.

  ```cpp
  // Game.cpp:41-43 — stats printed manually because operator<< does not exist
  cout << "HP: " << hero->getHp() << "/" << hero->getMaxHp()
       << "  ATK: " << hero->getAtk()
       << "  DEF: " << hero->getDef() << "\n";
  ```

- **Incomplete `operator==` for Item** (−1) — compares name and type but not value

  Two items with the same name and type but different power levels (e.g., a 3-ATK sword vs. a 7-ATK sword) will compare as equal, making it impossible to distinguish between them when searching an inventory or removing a specific item.

  ```cpp
  // Item.cpp:11-13 — operator== omits the value field
  bool Item::operator==(const Item& other) const {
      return name == other.name && type == other.type;
      // value is not compared — a Steel Sword (+3) equals an Ebony Sword (+7) by this logic
  }
  ```

**Clean Code note:**
The `Entity` / `Character` inheritance design is the highlight here — `Entity` cleanly handles the core character data and behavior, and `Character` extends it with stat-modification methods without duplication. Most helper functions are well-sized and focused; `drawHpBar` and `showMap` are examples of nice, single-purpose utilities. The main area to improve is the `battle()` function, where the loot block runs about 40 lines with inconsistent indentation and could easily be extracted into a `grantLoot()` helper. The `Inventory` class works but would benefit from explicit canonical form to make the resource management contract clear.
