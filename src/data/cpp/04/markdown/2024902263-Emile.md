- **No private member naming convention** (−6) — no trailing underscore on any private member; `using namespace std` in 4+ source files

  Without a naming convention for private members, local variables and member variables are visually indistinguishable — a reader cannot tell at a glance whether `name` on a given line refers to the object's field or a local parameter, which makes refactoring error-prone.

  ```cpp
  // Character.hh — private members with no trailing underscore or m_ prefix
  private:
      std::string name;    // indistinguishable from a local variable named name
      int maxHP;
      int currentHP;
      int atk;
      int def;
  ```

- **`dynamic_cast` in base class** (−2) — `CharacterBase::operator-=` casts `this` to `Character*` to call takeDamage; a base class depending on its derived class violates OOP — virtual dispatch should have been used

  A base class that must downcast to its own derived type to function has inverted the dependency — it can only work when the derived class exists, making it impossible to use CharacterBase with any other subclass and defeating the entire purpose of abstraction.

  ```cpp
  // Character.cpp:7-19 — base class downcasts itself to call a derived method
  CharacterBase& CharacterBase::operator-=(int damageAmount) {
      int newHP = getHP() - damageAmount;
      if (newHP < 0) newHP = 0;
      Character* derivedThis = dynamic_cast<Character*>(this);
      if (derivedThis != nullptr) {
          derivedThis->takeDamage(damageAmount);  // base depends on derived
      }
      return *this;
  }
  ```
