## Bonus

**Bonus score: 6 / 10**

Letting the player choose which enemy to fight rather than forcing a fixed order is a simple but genuinely good design decision — it gives the game replay agency that most projects don't have. The four enemies scaling in difficulty, each with their own loot drop and self-heal behavior, keeps the fights from feeling repetitive.

The ANSI color combat display with its dedicated HP bar function gives it real visual personality. Seeing your HP tick down in color feels better than it has any right to.

**Clean Code note:** The best structural decision here is the `Enemy` class extending `Character` to add a loot inventory — it's a clean and honest use of inheritance. The `operator<<` on Enemy showing loot is a nice extra touch. The main area to grow is function size: `battle()` is 218 lines and handles six action types, the equip/unequip submenu, and enemy turn logic all in one block — breaking those out into separate helpers would make it much easier to reason about. The ANSI color macros being defined in multiple files rather than one shared header is also worth cleaning up.
