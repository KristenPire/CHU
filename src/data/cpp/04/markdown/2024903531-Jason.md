**Inheritance — 0 / 10**
- Not used. Both `Player` and `Enemy` store a `Character character_` as a composition member and re-expose every getter manually — inheriting from `Character` instead would unify the HP/ATK/DEF interface and let `CombatSystem` accept either as a `Character&`, eliminating the parallel delegation boilerplate in both classes.

  Storing `Character character_` as a member inside Player and Enemy instead of inheriting from it means Player and Enemy cannot be used anywhere a `Character*` or `Character&` is expected — the entire combat and loot system must treat players and enemies as separate types with no shared interface, even though they share identical HP/ATK/DEF behavior.

  // player.hh — Character stored as composition member rather than base class
