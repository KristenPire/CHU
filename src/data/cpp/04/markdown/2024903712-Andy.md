**Heap / Dynamic Memory — 9 / 10**
- Inventory wraps `std::vector<Item>*` in a raw pointer with full correct Rule of Three (copy ctor, copy-assign, destructor). `battleLoop()` creates enemies as `std::unique_ptr<Enemy>` — idiomatic RAII.
- **Minor deduction** (−1) — wrapping a vector in a raw pointer is unnecessary indirection; the vector itself should be the member, eliminating the need for manual canonical form.

  Heap-allocating a vector that could simply be a value member adds one layer of indirection, forces manual memory management, and provides no benefit — `std::vector` is already a value type that owns its heap storage.

  ```cpp
  // sources/Inventory.cpp:1-4 — vector wrapped in raw pointer unnecessarily
  Inventory::Inventory() : items(new std::vector<Item>()) {}

  Inventory::Inventory(const Inventory& other)
      : items(new std::vector<Item>(*other.items)) {}
  // A plain `std::vector<Item> items;` member would need none of this
  ```

**Inheritance — 6 / 10**
- Enemy inherits from Character — genuine is-a relationship; adds expReward, goldReward, overrides attack()
- **No virtual destructor** (−2) — Character.hh has no virtual destructor; deleting an Enemy via Character* is UB

  If any code ever deletes an `Enemy` through a `Character*`, only `Character`'s destructor runs — `Enemy`'s destructor is silently skipped, which is undefined behavior and can leak resources.

  ```cpp

  class Character {
  public:
      Character(const std::string& name, int hp, int basic_atk, int basic_def,
                int level, int max_exp, int exp);
      // ~Character() not declared virtual — deleting Enemy via Character* is UB
      std::string getName() const;
      // ...
  ```

- **No polymorphic dispatch** (−2) — enemies are created as `unique_ptr<Enemy>` and used directly as Enemy; no base-class pointer usage in the game loop

  Inheritance without polymorphic dispatch is just code reuse through inheritance — the point of a virtual-method hierarchy is that a `Character*` can point to any subtype and call the right method automatically, which never happens here.
