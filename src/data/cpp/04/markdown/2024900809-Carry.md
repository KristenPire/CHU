- **Variable shadowing** (−2) — in all three fight functions, `int turn` (outer counter) is shadowed by `TurnResult turn = processPlayerTurn(...)` (inner scope, Game.cpp:94, 161, 220); should be renamed `turnResult` or `outcome`; same error repeated three times

  A variable that shadows an outer name makes the outer variable unreachable within that inner scope without a rename, and compilers will warn about it — reading the code requires extra attention to figure out which `turn` is being referenced at each point.

  ```cpp
  // Game.cpp:70 and 94 — fightJiaqiu(): int turn is declared, then shadowed by TurnResult turn
  int turn = 0;               // outer counter, incremented each iteration
  // ...
  TurnResult turn = processPlayerTurn(jiaqiu, EnemyHitSource::JiaQiu);  // shadows outer turn
  if (turn == TurnResult::Defeat)   // which 'turn' is this?
      return false;
  ```

- **Magic number 999** (−2) — `jiaqiu.takeDamage(999)` and `leiheng.takeDamage(999)` for mercy/story endings — should be a named constant or dedicated method

  Using a large magic number to simulate an instant kill is fragile: if a character's HP is ever initialized above 999 (e.g., a difficulty mode or scaling), the "instant kill" silently stops working with no compiler warning.

  ```cpp
  // Game.cpp:81 — magic 999 used as instant-kill for mercy ending
  if (parley == JiaqiuParleyOutcome::MercyEndBattle) {
      jiaqiu.takeDamage(999);   // should be kInstantKillDamage or jiaqiu.kill()
      Ui::waitForEnter();
      break;
  }
  ```

- `rand()` seeded via `srand(time(nullptr))` — acceptable but not thread-safe; `applyCritical()` and `applyLinDaiyuAssist()` are small and focused
