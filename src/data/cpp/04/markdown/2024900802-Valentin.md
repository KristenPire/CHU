- **Missing virtual destructor on Card** (−2) — CardManager deletes via `Card*`; derived classes with member data (e.g., EmergencyHeal's `healMultiplier_`/`healAmount_`) will not have their destructors called — undefined behavior

  CardManager calls `delete card` on `Card*` pointers, but without a virtual destructor on `Card`, the compiler calls only `Card::~Card()` — the destructor of the actual derived class (e.g., `EmergencyHeal` with its `healMultiplier_` and `healAmount_` members) is silently skipped, which is undefined behavior.

## Bonus

**Bonus score: 9 / 10**

Nine distinct card types with real mechanical differences, an energy system, and six bosses that each require a different approach — Valentine mimicking your last card, Rhys forcing a three-action turn limit, Stephen going invincible mid-fight. That's a lot of design work per boss.

Naming the bosses after classmates is a great touch that gives the whole thing a personal edge. The card collection loop where beating bosses unlocks new cards makes it feel like a real roguelite.

**Clean Code note:** The 25-file architecture — with BattleManager, BossLogic, CardFactory, CardManager, Energy, Damage, Effect, and UI all as dedicated classes — is impressively well-organized. The trailing underscore convention is used consistently throughout all files, and method names like `processPlayerTurn`, `processBossTurn`, `calculatePlayerDamage`, and `updateEffects` are precise and self-documenting. The main technical gap is the missing virtual destructor on the `Card` base class, which causes undefined behavior when `CardManager` deletes Card* pointers — since derived classes like `EmergencyHeal` have their own member data, this is a real issue worth fixing. The debug menu options left in production are a minor oversight that's easy to miss under submission pressure.
