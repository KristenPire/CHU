## Overall

A rogue-lite dungeon crawler with a genuine Slay-the-Spire-inspired AP/intent system: enemies telegraph their moves, you manage action points, and a six-type monster roster escalates across 10 floors. The main strength is architectural ambition — a five-file Game split and a full AP/CD item system show real game-design thinking. The critical weakness is that the Character and Item classes were completely redesigned from scratch, dropping every required interface method and all four operator overloads, which zeroed out two entire scoring sections.

## Sections

**Subject Requirements — 22 / 30**
- Game loop, end conditions, and README are all solid — full marks on mechanics and repository
- **Character interface rewritten** (−3) — No `getName()`, `getHP()`, `getATK()`, `isAlive()`, `takeDamage()`, or `operator<<`; the class uses raw public data members instead of the required encapsulated interface

  Any code that tries to call `character.getHP()` will fail to compile because the method simply does not exist, making the Character class incompatible with every piece of code that follows the required interface.

  ```cpp
  // Character.cpp:4 — constructor uses public data members instead of the required interface
  Character::Character() : level(1), hp(30), maxHp(30), ap(3), maxAp(3), gold(0), tempArmor(0) {
      inventory.addItem(Item("Rusty Iron Sword", 4, 0, 0));
  }
  // No getName(), getHP(), getATK(), isAlive(), takeDamage(), or operator<<
  ```

- **Item interface rewritten** (−3) — No `getName()`, `getType()`, `getValue()`, `operator==`, or `operator<<`; replaced by a completely different public-member design

  Without the standard `getType()` and `getValue()` accessors, Item objects cannot be used by any code that expects the required interface, and the absence of `operator==` makes it impossible to compare two items for equality.

  ```cpp
  // Item.cpp:5-6 — 8-parameter constructor replaces the required (name, Type, value)

        realDamage(real), nextTurnAPBuff(apBuff), armorBreaker(armorBrk) {}

  ```

- **Inventory missing isEmpty() and operator<<** (−2) — addItem and size are correct, canonical form is correct, but two required members are absent

  Code that calls `inventory.isEmpty()` to guard against using an empty inventory will not compile, forcing callers to use `inventory.size() == 0` as a workaround — an inconsistency that grows as the codebase does.

  ```cpp

  size_t Inventory::size() const {
      return items.size();
  }
  ```
