**Clean Code — 34 / 40**
- Exceptional function decomposition: `run()` (4 lines), `spawnEnemy()` (10 lines), `showStatus()` (7 lines), `useItem()` (5 lines), `nextFloor()` (17 lines) — all short and single-purpose
- Correct Inventory canonical form with STL vector; no raw pointers anywhere
- **`combatLoop()` too long** (−2) — ~42 lines handling the full turn loop inline; extracting `processEnemyTurn()` and `processPlayerAttack()` would improve it

  A 42-line function with interleaved player input, attack resolution, death checks, and enemy retaliation is hard to unit-test and makes it difficult to add features like status effects or special attacks without the function growing further.

  ```cpp
  // Game.cpp:46 — combatLoop() mixes input, attack, death check, and enemy retaliation in one loop
  void Game::combatLoop() {
      while (hero.isAlive()) {
          showStatus();
          int choice; cin >> choice;
          if (choice == 1) {
              enemy.takeDamage(hero.getATK());
              if (!enemy.isAlive()) { nextFloor(); continue; }
              hero.takeDamage(enemy.getATK());  // enemy retaliation inline
          }
          else if (choice == 2) { useItem(); }
      }
  ```

- **Broken item system** (−3) — `useItem()` calls `hero.heal(10)` directly with a hardcoded value, without consulting inventory stock or removing the item; the Peach can be used indefinitely regardless of inventory state

  An item system that never decrements inventory allows infinite healing with no resource cost, which breaks any difficulty balance the game intends — and calling `heal(10)` regardless of the item's actual value means Weapon and Armor items would also silently heal the player.

  ```cpp
  // Game.cpp:90 — useItem() ignores inventory entirely; hardcoded heal with no removal
  void Game::useItem() {
      cout << "\n┌─────────────────────────────────────┐" << endl;
      cout << "│        You used a peach!            │" << endl;
      cout << "└─────────────────────────────────────┘" << endl;
      hero.heal(10);   // hardcoded; inventory never checked or modified
  }
  ```

- **`exit(0)` for win** (−1) — bypasses future cleanup; `using namespace std` in Game.cpp

  Calling `exit(0)` skips all destructors for objects on the stack and bypasses any cleanup logic in `run()` — if file handles, network connections, or save-game logic are ever added, this will silently skip them.

  ```cpp
  // Game.cpp:97 — exit(0) used for win condition instead of returning
  void Game::nextFloor() {
      if (currentFloor == 3) {
          cout << "        CONGRATULATIONS! YOU WIN!        \n";
          exit(0);   // skips ~Game() and any cleanup in run()
      }
  ```
