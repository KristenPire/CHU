## Overall

"Shadow of the Crypt" is a dungeon-crawler RPG where an adventurer explores four rooms — an Entrance Hall, an Armory, an Armor Chamber, and the boss Crypt — to defeat a Lich. The progression design is deliberate: the starting stats make a direct run at the Lich near-certain death, so the player must clear both side rooms to pick up the Longsword (+5 ATK), Iron Shield (+4 DEF), and Healing Potions before the final fight. The student added a `Room` class beyond the skeleton, used `std::unique_ptr` throughout `Room` and `Game`, and implemented a clean `enemyPrototype_` pattern so fleeing from a room resets the enemy correctly. All four required operators, all five required classes, and a complete win/lose flow are present. Main issues are a large `fightLoop()` function that should be decomposed, and the entire Windows build directory committed to the repository.

## Bonus

**Bonus score: 7 / 10**

The game is complete and actually balanced — not just technically compliant. Starting stats (HP 25, ATK 5, DEF 2) versus the Lich (HP 40, ATK 12, DEF 3) mean the adventurer will lose unless they find the Longsword and Iron Shield first; the design forces exploration and rewards the player for reading the README. The flee mechanic uses a random 50/50 chance and correctly resets the enemy on success via `Room::resetEnemy()` (Room.cpp:32–36), so escaping a fight doesn't permanently clear the room — a thoughtful touch.

The `enemyPrototype_` pattern in `Room` (Room.hh:35, Room.cpp:9–10) — storing a clean copy of the enemy alongside the live one to enable resets — shows real design thinking. The `Room` abstraction itself is well-scoped: it encapsulates name, description, enemy, items, and exits cleanly, and the `Game` class delegates room logic to it appropriately.

The main areas to push further: (1) split `fightLoop()` into helper functions, (2) add inheritance — having `Enemy` or `Boss` extend `Character` would unlock the full score and make the Lich fight feel architecturally distinct from regular combat.
