## Bonus

**Bonus score: 9 / 10**

The BattleTurnInput strategy pattern is a genuinely smart call — decoupling the input source from game logic so you can swap in a scripted input for testing isn't something most students think to do at this scale, and it shows real architectural instinct.

The game itself is polished end to end: three hero classes each with a distinct skill, four biomes, a branching route, equipment slots, and level-up progression. The k-prefix named constants in the anonymous namespace are a nice finishing touch — it makes the numbers easy to find and tune.

**Clean Code note:** The decomposition is impressive — 50+ named private methods in Game, all short and focused, with clear responsibilities. The k-prefix anonymous namespace constants and m_ prefix throughout are consistently applied. The one area that stands out is Inventory.cpp, which uses C-style iterator loops (std::vector<Item>::const_iterator) where the rest of the project uses modern C++11 style — it feels like a different hand wrote that file. Replacing those with range-based for loops would bring the whole codebase to a uniform modern standard.
