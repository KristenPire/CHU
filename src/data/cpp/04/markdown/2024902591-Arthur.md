- **`rand() % enemys.size() - 1` operator precedence bug** (−2) (Game.cpp:165) — computes `rand() % (enemys.size() - 1)` due to precedence; excludes the last enemy and causes UB when `enemys.size()` is 1

  When `enemys.size()` is 1, `enemys.size() - 1` evaluates to 0 (unsigned), making `rand() % 0` undefined behavior; even when the size is larger, the last enemy can never be selected, silently breaking the game balance.

  ```cpp
  // Game.cpp:165 — operator precedence bug
  int enemyIndex = rand() % enemys.size() - 1;
  // parsed as: (rand() % enemys.size()) - 1  — NOT rand() % (enemys.size() - 1)
  // but unsigned subtraction: if result is 0, 0-1 wraps to a huge index
  // correct expression: rand() % enemys.size()
  ```

- **No virtual destructor** (−2) — Character has virtual methods but NO virtual destructor; deleting a derived class via `Character*` is undefined behavior

  The rule is simple: any class with at least one virtual method must have a virtual destructor; without it, `delete characterPtr` where `characterPtr` points to a `HumanPlayer` or `Enemy` calls only `~Character()`, skipping the derived destructor and leaking anything the derived class owns (including its Inventory).

  ```cpp
  // include/Character.hh — virtual methods present, no virtual destructor
  class Character
  {
  public:
      // ...
      virtual void useItemIndex(Character& otherPlayer);
      virtual void useSkillIndex(Character& otherPlayer);
      // ~Character() not declared — compiler generates non-virtual one
      // deleting Enemy* via Character* is undefined behavior
  ```

- **Design deduction** (−1) — Character has no virtual destructor despite being a polymorphic base; this is the defining rule for any class with virtual methods
