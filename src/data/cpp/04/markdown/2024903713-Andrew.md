- **`using namespace std;` in header** (−4) — `Character.hh:6` exports `std` to every file that includes it; same in `Game.cpp`

  `using namespace std` in a header file is not confined to that header — it contaminates every file that includes it directly or transitively, making standard names like `size`, `min`, `max`, and `count` available without qualification across the entire project.

  ```cpp
  // Character.hh:6 — using namespace std exported to all includers
  #ifndef CHARACTER_HH
  #define CHARACTER_HH
  #include <iostream>
  #include <string>
  using namespace std;   // affects every .cpp that includes Character.hh
  class Character { ... };
  ```

- **Note** — unscoped `enum Type { HEAL, DOUBLE_ATK_NEXT, BOOST_ATK_PERM }` could conflict with other identifiers; should be `enum class`

  An unscoped enum injects its enumerators directly into the enclosing scope, so `HEAL`, `DOUBLE_ATK_NEXT`, and `BOOST_ATK_PERM` become global names that can silently clash with any macro, variable, or function using the same name elsewhere.

  ```cpp
  // Item.hh — unscoped enum; enumerators leak into enclosing scope
  enum Type { HEAL, DOUBLE_ATK_NEXT, BOOST_ATK_PERM };
  // Should be:
  // enum class Type { Heal, DoubleAtkNext, BoostAtkPerm };
  ```
