## Section 4 — Heap / Dynamic Memory: 6 / 10

> Mode: RAW POINTERS

`currentEnemy` is a `Character*` allocated with `new` in `spawnEnemy()` (Game.cpp:91, 108) and deleted in `battle()` (Game.cpp:124) after the enemy is killed. After deletion `currentEnemy = nullptr` is set (Game.cpp:125) — no dangling pointer on the normal path. However, `startLevel()` (Game.cpp:69) returns early `if (!hero.isAlive())` without deleting `currentEnemy` — if the hero dies mid-fight, the current enemy `Character` object is leaked. `clearBattle()` (Game.cpp:239) sets `currentEnemy = nullptr` without first deleting, which would leak if ever called while an enemy is alive (in practice only called after `checkLevelClear`, where the enemy is already deleted, but the function's contract is unsafe). The normal win path is leak-free; the hero-death path leaks one allocation.
