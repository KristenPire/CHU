## Bonus

**Bonus score: 7 / 10**

The rest-or-push tension is the game's best design decision — resting recovers HP but carries a 30% ambush chance, and the ambush gives the enemy a free strike before the player can act. That risk/reward loop gives most turns a real decision. The critical hit system (20% chance for 1.5× damage) and the 50% flee chance that walks the player back a floor both add texture to combat without complicating it.

The five-floor structure with a named final boss (Demon Lord) gives the run clear shape: the dungeon feels like it's actually going somewhere. The dramatic preamble on the boss floor ("THE AIR GROWS HOT") is a nice touch.

**Clean Code note:** The function decomposition is good at the top level — `run()` delegates to `displayMenu()`/`handleInput()`, and `explore()`/`rest()`/`handleItemUse()` are all focused. The one function that needs breaking up is `startBattle()`, which at 88 lines handles input parsing, critical-hit calculation, escape attempts, enemy retaliation, and win/loss detection all in one body — extracting `resolvePlayerAttack()`, `resolveEnemyAttack()`, and `attemptEscape()` would fix it. The other habit worth addressing is the scatter of raw probability and stat values throughout Game.cpp: `MAX_FLOORS` shows the student knows how to use named constants, so applying the same practice to the combat numbers (crit chance, ambush probability, enemy stats) would make the game much easier to balance.
