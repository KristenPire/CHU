## Section 2 — Clean Code: 26 / 40

### 2.1 Function Size & Focus: 8 / 12
`Character.cpp` and `Item.cpp` functions are short and focused. `run()` in `Game.cpp` delegates to several named helpers which is a positive signal, but `combat()` runs approximately 90 lines mixing display with game logic and should be decomposed further. `exploreLocation()` contains a switch with branches that each handle multiple responsibilities.

### 2.2 Canonical Form: 8 / 10
`Inventory` uses a raw pointer to a `std::vector<Item>`. Copy constructor performs a deep copy (`Inventory.cpp:9`), copy-assignment has a self-assignment guard (`Inventory.cpp:15`), and the destructor frees the allocation (`Inventory.cpp:25`). `Game` owns a raw `Character*` but does not define a destructor or copy constructor — Rule of Three is satisfied for `Inventory` but violated for `Game`.

### 2.3 Naming: 8 / 10
Member variables use a consistent underscore suffix throughout (`player_`, `enemies_`, `currentLocation_`). Function names in `Game.hh` are descriptive actions: `initializeGame()`, `combat()`, `exploreLocation()`, `useItem()`. A few local variables in `Game.cpp` use short names (`ch`, `opt`) that reduce readability in longer functions.

### 2.4 Style & Readability: 2 / 8
Indentation is consistent across `Character.cpp`, `Item.cpp`, and `Inventory.cpp`. `Game.cpp` contains several magic numbers for player stats, damage values, and heal amounts without named constants, and multiple commented-out blocks remain in the final submission. Blank line placement in `Game.cpp` is irregular.
