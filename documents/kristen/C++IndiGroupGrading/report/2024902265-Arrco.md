## Overall

"Hero's Trial" is a three-level terminal RPG where the hero fights through waves of monsters and bosses, earns gold, and spends it in a shop on swords, armor, and potions. The structure is clear and the game is functional end-to-end: levels unlock sequentially, the shop updates stats permanently, and defeating the Level 3 boss produces a clean win. The primary technical weaknesses are: a death condition that resets HP and loops instead of terminating (making the player immortal), incomplete `operator<<` implementations on both `Item` and `Inventory` that silently drop non-potion items, no inheritance, and a `currentEnemy` memory leak on the hero-death path. The codebase is compact, readable, and shows a real understanding of the required interfaces — the gaps are in the details.

## Bonus

**Bonus score: 3 / 10**

The game works and the three-level structure with a shop is a coherent design choice. The stat progression — swords and armor that permanently increase ATK/DEF, potions as consumables — creates a real upgrade loop. The boss-per-level format with escalating stats gives the game forward momentum.

The ambition ceiling here is low: no story, no room exploration, no dialogue, no special abilities. The enemies are statistically differentiated but mechanically identical — every fight is the same "you attack, enemy attacks" exchange. The shop items are named `Sword 1/2/3` and `Armor 1/2/3`, which are placeholder names rather than designed ones. The README describes the game accurately but with no atmosphere.

The implementation shows the student understands the required class interfaces and can wire them into a working game loop. The main structural lesson is to replace raw stats with a richer model — if `Monster` and `Boss` were separate subclasses of `Character` with distinct `attack()` behaviors, both the code and the game would be more interesting.
